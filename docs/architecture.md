# Техническая архитектура

Стек согласован владельцем 17 ноября 2026 в задаче 02.
Основная ветка `main`; рабочая `feat/02-repository-architecture`.
Карточка: https://trello.com/c/wqm5mrvu.

## Согласованные решения

- Клиент: TypeScript, Vite; Canvas 2D для будущей игры, HTML/CSS для меню.
- API: Node.js, TypeScript, Fastify. Один процесс раздаёт клиент и API.
- Хранение: SQLite на постоянном диске. В 02 база не создаётся и драйвер
  не устанавливается. Схема, миграции и операции относятся к 09/10.
- Размещение: один экземпляр Node.js, постоянный диск и TLS перед ним.
  Провайдер, тариф, домен и резервные копии выбираются в 15.
  Платные обязательства не создавались.
- Автоматические браузеры: Chromium и WebKit. Физические устройства
  и конкретные версии Chrome/Safari уточняются перед приёмкой.
  Эмуляция не доказывает работу на реальном iPhone.

## Границы модулей

- `client/games/ilsur-lovit-chleny/` содержит HTML, стили, TypeScript и ассеты
  первой игры. Маршрут игры — `/ilsur-lovit-chleny/`.
- `client/games/ilsur-platformer/` содержит основу третьей игры с Canvas 2D.
  Закрытый прямой маршрут — `/ilsur-platformer/`; в каталог игра пока не входит.
- `client/public/catalog/` содержит стили и превью каталога на `/`.
- `client/public/login/` содержит стили и портрет для общего входа на `/login`.
  Игра использует тот же портрет.
- Fastify формирует страницы каталога и входа. Vite собирает HTML игры,
  который Fastify отдаёт после проверки сессии.

`client/games/ilsur-platformer/game.ts` содержит детерминированную физику,
прыжок, приседание, выстрелы и следящую камеру. `input.ts` объединяет клавиши
и независимые pointer ID для одновременных касаний; `scene.ts` рисует состояние
мира на Canvas. Время кадра передаётся в игровую логику явно, чтобы тесты могли
воспроизводить движение, столкновения и переходы состояний.

`server/app.ts` создаёт приложение без открытия порта: интеграционные тесты
используют Fastify inject. `server/config.ts` проверяет настройки.
`server/main.ts` открывает порт, при ошибке пишет серверный лог,
закрывает приложение и устанавливает ненулевой код выхода.
Статика находится относительно модуля: `client` в разработке,
`dist/client` после сборки. Рабочая папка терминала на выбор пути не влияет.

В 09/10 HTTP-контракты, валидация, сессии, лимиты запросов и идемпотентность
записи партии разрабатываются вместе с тестами отдельно от слоя SQLite.
Клиентский результат не защищает от подделки очков; уровень защиты
общего рейтинга необходимо определить в задаче 10.

## Данные и секреты

Будущие сущности: сессия, ник, партия, лучший результат. Ник не является
уникальной учётной записью: использование чужого ника разрешено правилами.
Точная схема и API пока не реализованы и не утверждены как контракт.

Общий пароль, ключ сессий и путь SQLite хранятся только на сервере.
Не использовать префикс `VITE_` для секретов — он раскрывает их клиенту.
`.env`, `data`, SQLite, зависимости, сборка и отчёты исключены из Git.
`.env.example` содержит безопасные примеры и названия будущих параметров.

## Проверки

Для основы подготовлены модульные, интеграционные, браузерные и layout/visual
проверки. Порог покрытия 100% всего собственного исполняемого кода.
CI настроен выполнять обязательные команды на каждом PR, но ещё не запускался.
Lock-файл создан установкой npm. Модульные/интеграционные тесты и покрытие
прошли; браузерный запуск блокирует запрет открытия порта в среде разработки.
Шесть проверенных Linux эталонов Chromium/WebKit хранятся рядом с тестами
в Git: `tests/e2e/foundation.spec.ts-snapshots/`. Они привязаны к версии кода.
CI сравнивает с ними без автоматического обновления и без внешней загрузки.
Срок хранения артефактов больше не влияет на доступность эталонов.
Локальные эталоны macOS/Windows остаются в игнорируемой `.visual-baselines/`.
Actual/diff, видео, трассы и отчёты не входят в Git. Новые и изменённые эталоны
принимаются только после просмотра всех затронутых изображений.
Предыдущий Ubuntu CI прошёл, новый запуск с эталонами из Git ещё не выполнен.

Задача 03 расширяет инфраструктуру под таймеры, случайность, будущие модули
игры и хранилища, а также проверяет намеренное падение теста/порога.
Подготовка основы не закрывает задачу 03.
