# Ильсур ловит члены

Закрытая браузерная аркада для компании друзей.
Игра и вход доступны локально. Общий рейтинг находится в разработке.

## Окружение и установка

Node.js 22.13+ и npm (`nvm use`, если установлен nvm).

```sh
npm install
npx playwright install chromium webkit
```

Первая установка создаёт `package-lock.json`: его необходимо проверить
и включить в согласованный коммит. После этого использовать `npm ci`.
Lock-файл создан реальной установкой npm. Чистая повторная установка
`npm ci` пока не проверена из-за сетевых ограничений среды разработки.

## Локальный запуск

Скопируйте `.env.example` в `.env` и задайте согласованный пароль в
`GAME_PASSWORD`. Пароль чувствителен к регистру.

```sh
cp .env.example .env
npm run dev
```

Откройте http://127.0.0.1:3000. Команда собирает клиент и запускает Fastify.
После изменения кода перезапустите команду. Для запуска готовой сборки
используйте `npm start`. Сервер автоматически читает `.env`.

После входа откроется закрытый каталог игр. Каталог доступен по `/`, а игра
«Ильсур ловит члены» — по `/ilsur-lovit-chleny/`, «Ильсур-Пакман-Членоед» —
по `/packman/`. Перед запуском обе игры показывают короткую инструкцию.
Переход к игре без сессии сначала потребует вход; из меню паузы можно
вернуться в каталог, сохранив сессию.

Для проверки с телефона из той же Wi-Fi сети задайте `HOST=0.0.0.0` в `.env`
и откройте `http://<IP-Mac>:3000`. Для первой игры нужен горизонтальный экран,
для «Ильсур-Пакман-Членоед» — вертикальный.
На сервере с HTTPS задайте `NODE_ENV=production` для защищённой cookie.
Файл `DATABASE_PATH` по умолчанию находится в `./data/game.sqlite`.
Храните его на постоянном диске, чтобы профили и сессии переживали перезапуск.

Ник содержит от 1 до 32 символов, крайние пробелы удаляются, регистр
при поиске профиля игнорируется. В игре сохраняется исходное написание.
Сессия действует 7 дней. Для выхода откройте паузу. После 10 неверных
паролей с одного IP вход блокируется до конца минутного окна.

## Проверки

```sh
npm run typecheck
npm run build
npm test
npm run test:e2e
npm run format:check
```

Если порт 3000 занят, E2E-сервер можно перенести, например:
`PLAYWRIGHT_PORT=3001 npm run test:e2e`.

`npm run check` запускает сборку, тесты покрытия и браузерные тесты.
Playwright сначала собирает проект и запускает сервер на свободном порту 3000.
Отчёты: `coverage/index.html`, `coverage/coverage-summary.json`.
Порог 100% строк, функций, ветвей и statements. Включены все файлы
исполняемого кода в `server`, `client`, `scripts`, включая неимпортированные.
В клиенте сейчас только HTML/CSS; собственных служебных скриптов нет.

Проверенные Linux эталоны Chromium/WebKit хранятся в Git рядом с тестами
в `tests/e2e/foundation.spec.ts-snapshots/`. Обычный CI использует эталоны
этого коммита, без скачивания из временных артефактов.
Для изменения внешнего вида создать кандидаты на Linux с браузерами из lock-файла:

```sh
npm run test:visual -- --update-snapshots
```

Просмотреть каждый PNG и различия: читаемость, отсутствие обрезки,
размеры 1280×720, 844×390, 390×844 в обоих браузерах. Только после просмотра
включать эталоны в согласованный коммит. Обычный CI не принимает новые эталоны
автоматически; отсутствие и несовпадение эталона считаются ошибкой.

На macOS/Windows локальные эталоны сохраняются в игнорируемой `.visual-baselines/`.
Они не заменяют Linux эталоны CI. Actual/diff, промежуточные снимки, видео,
трассы и отчёты не коммитятся; их можно хранить в артефактах CI с ограниченным сроком.
Для частичной проверки поведения: `npm run test:e2e -- --grep-invert @visual`;
это не заменяет полный Linux CI.

| Критерий                            | Проверка                                                 |
| ----------------------------------- | -------------------------------------------------------- |
| API, статика, CSS, 404              | `tests/unit/app.test.ts`, E2E собранного сервера         |
| Параметры и ошибки запуска          | `tests/unit/config.test.ts`, `tests/unit/main.test.ts`   |
| Типы и сборка                       | `npm run build`                                          |
| Клавиатура, ссылка, ошибки страницы | `tests/e2e/foundation.spec.ts`                           |
| Размеры ПК/телефона и внешний вид   | layout и visual тесты того же файла                      |
| Воспроизводимость                   | чистый `npm ci`, Linux CI после появления lock-файла     |
| Отсутствие секретов                 | проверка diff и `dist/client`, секреты только на сервере |
